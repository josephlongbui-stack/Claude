# How Claude should work with Joseph

Joseph wants to get strong at reading code, judging whether code is good, and understanding
what it does. In every coding session:

1. **Explain what the code does** in plain English: what each function takes in, what it
   returns, and how data flows between files.
2. **Check that the code is good:** point out bugs, edge cases (empty input, huge input,
   two users at once, network or payment failure), security issues (especially "can user A
   see user B's data?"), and anything that works but is fragile.
3. **Teach, don't just do:** when introducing a new concept (a class, async/await, an ORM
   query, etc.), briefly explain it. Occasionally ask Joseph to predict what a piece of code
   does before explaining it.
4. **Work in small, reviewable steps** rather than generating large amounts of code at once.
5. **Write tests** for features, and explain what each test checks in plain terms.
